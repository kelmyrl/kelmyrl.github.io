Sales Data Dashboard

A Next.js application that reads sales records from a Supabase database and displays them on a webpage, deployed on Vercel with automatic builds triggered from GitHub.

Next.js Supabase Vercel React
View Live App ↗ GitHub Profile

Overview

This project is an early-stage prototype for tracking and presenting sales metrics. The current version connects to a Supabase database and pulls a table of sales records — timestamps, quantities, and values — rendering them directly on the page. It's intentionally simple right now: the focus so far has been getting the data pipeline and deployment working end to end, with the UI to be built out from there.

How it works

The app is built with Next.js. On page load, it queries a Supabase project (a hosted Postgres database with an auto-generated API) using the Supabase JavaScript client, and renders the returned rows as a list on the page. Supabase handles the database and API layer; Next.js handles fetching that data and turning it into HTML.

The pipeline, step by step

  1. Write code locally. The app is a standard Next.js project — pages/components, plus the Supabase client configured with a project URL and API key.
  2. Push to GitHub. The project lives in a GitHub repository. Every commit pushed to a branch updates the remote history that Vercel watches.
  3. Vercel is connected to the repo. Through Vercel's GitHub integration, the project is linked once; from then on, Vercel listens for new commits instead of requiring a manual deploy step.
  4. Every push triggers a build. On a push to a feature branch or pull request, Vercel automatically builds the app (next build) and publishes a unique preview deployment URL, so changes can be checked before they go live.
  5. Merging to main deploys to production. When changes are merged into the main branch, Vercel builds again and promotes that build to the production URL (semapi-three.vercel.app) — no manual server setup or hosting configuration required.
  6. Supabase credentials stay out of the repo. The Supabase project URL and API key are stored as environment variables in Vercel's project settings, not committed to GitHub, and are injected into the app at build/runtime.

Why this setup

This is the standard workflow Vercel is built around: it's made by the creators of Next.js, so the two are tightly integrated (zero-config builds, serverless functions, edge rendering, etc.), and connecting a GitHub repo gets continuous deployment — every push is automatically built and shipped — without needing to manage a server. Supabase fills the backend role, giving the app a real database and API without writing custom backend code.

Status & next steps

Right now the app only reads and displays data. Planned next steps include building out the UI (tables/charts instead of a raw list), adding the ability to write new sales entries, and adding basic auth via Supabase.
